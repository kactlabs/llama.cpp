# Git Guide for llama-rs

## What to Include in Git ✅

### Source Code
- ✅ `crates/` - All Rust source code
- ✅ `tools/` - Tool source code (llama-cli, llama-server, etc.)
- ✅ `examples/` - Example programs
- ✅ `Cargo.toml` - Workspace configuration
- ✅ `*/Cargo.toml` - All crate manifests

### Documentation
- ✅ `*.md` - All markdown documentation
- ✅ `README_RUST.md`
- ✅ `RUST_CONVERSION_PLAN.md`
- ✅ `CONVERSION_STATUS.md`
- ✅ `QUICKSTART.md`

### Configuration
- ✅ `.gitignore` - Git ignore rules
- ✅ `rust-toolchain.toml` - Rust version specification (if created)
- ✅ `.cargo/config.toml` - Cargo configuration (if created)

### CI/CD (when created)
- ✅ `.github/workflows/*.yml` - GitHub Actions
- ✅ `Dockerfile` - Docker configuration (if created)

## What to Exclude from Git ❌

### Build Artifacts
- ❌ `target/` - **NEVER commit this!**
  - Contains compiled binaries
  - Contains intermediate build files
  - Can be 100s of MB to GBs
  - Regenerated by `cargo build`

### Dependency Lock (for libraries)
- ❌ `Cargo.lock` - For library crates (optional)
  - ✅ Keep for binary/application crates
  - ❌ Exclude for library crates
  - Our case: Mixed (workspace), so we're excluding it

### IDE Files
- ❌ `.vscode/` - VS Code settings (unless shared)
- ❌ `.idea/` - IntelliJ/CLion settings
- ❌ `*.swp`, `*.swo` - Vim swap files
- ❌ `.DS_Store` - macOS metadata

### Temporary Files
- ❌ `*.rs.bk` - Backup files from cargo fix
- ❌ `*.orig` - Merge conflict backups
- ❌ `*.rej` - Patch reject files

### Test/Benchmark Data
- ❌ `*.gguf` - Model files (too large)
- ❌ Test output files
- ❌ Benchmark results (unless documented)

## Git Commands

### Initial Commit
```bash
# Check what's new
git status

# Add Rust files
git add Cargo.toml
git add crates/
git add tools/
git add examples/
git add *.md
git add .gitignore

# Verify target/ is NOT staged
git status | grep target  # Should show nothing

# Commit
git commit -m "feat: Initialize Rust conversion with GGUF parser

- Add Cargo workspace structure
- Implement complete GGUF format parser
- Add stub crates for GGML and llama layers
- Add tool scaffolding (cli, server, bench)
- Add comprehensive documentation
- Add gguf-info example tool

Phase 1 complete: Foundation and GGUF support"
```

### Verify Ignore Rules
```bash
# This should NOT show target/
git status

# Verify target/ is ignored
git check-ignore -v target/
# Should output: .gitignore:X:/target/    target/
```

### Clean Untracked Files (if needed)
```bash
# See what would be removed
git clean -ndx

# Remove build artifacts (careful!)
git clean -fdx target/
```

## File Size Guidelines

### Keep in Git:
- Source files: < 100 KB each (typical)
- Documentation: < 1 MB total
- Configuration: < 10 KB each

### Never in Git:
- Build artifacts: Can be GBs
- Model files: Usually 100s of MBs to GBs
- Large binary files: > 10 MB

## Best Practices

1. **Always check before committing**
   ```bash
   git status
   git diff --cached
   ```

2. **Never commit target/**
   - It's regenerated by `cargo build`
   - Wastes repository space
   - Causes merge conflicts

3. **Commit logical units**
   - One feature per commit
   - Clear commit messages
   - Reference issues/PRs

4. **Keep commits clean**
   - No debug code
   - No commented-out code
   - No temporary files

5. **Use branches**
   - `main` - stable code
   - `develop` - integration
   - `feature/*` - new features
   - `fix/*` - bug fixes

## Repository Size

### Current (C++ only):
- ~50 MB (source code)

### After Rust Addition:
- ~51 MB (source + Rust code)
- `target/` would add 100s of MB (DON'T COMMIT!)

### With Proper .gitignore:
- Repository stays lean
- Fast clones
- No bloat

## Summary

**DO commit:**
- ✅ All `.rs` source files
- ✅ All `Cargo.toml` files
- ✅ Documentation (`.md` files)
- ✅ Configuration files

**DON'T commit:**
- ❌ `target/` directory
- ❌ Build artifacts
- ❌ IDE-specific files
- ❌ Model files (`.gguf`)

**The `target/` folder is the Rust equivalent of C++'s `build/` directory - it should NEVER be in version control!**
